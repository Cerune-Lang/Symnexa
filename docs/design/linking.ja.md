# Symnexaのリンカ実装

[English](linking.en.md) · [資料一覧](../README.md)

Symnexaは、入力オブジェクトのシンボルとリロケーションを解決し、実行ファイルを生成するツールです。最初はLiseOSに必要なx86-64 ELF64だけを対象とします。**Rust製の初期実装があります。**対応する形式とリロケーションは入力に応じて制限します。

## 入力と出力

| 項目 | 対応内容 |
| --- | --- |
| 入力 | x86-64、リトルエンディアンのELF64 ET_REL |
| 出力 | ELF64 ET_EXEC |
| 入口 | `main`シンボル |
| 配置開始 | `0xffffffff80000000` |
| セクション | `.text`、`.rodata`、`.data`、`.bss`、Limine用のデータ |
| プログラムヘッダ | 読み込み専用／実行可能／書き込み可能な`PT_LOAD` |
| 除外 | 動的リンク、共有ライブラリ、TLS、PE実行ファイル |

入力ファイルの形式と生成先のABIは別々に扱います。COFF入力への対応は、ELFでの起動検証が済んでから検討します。

## リンク処理

1. ELFヘッダ、セクションヘッダ、シンボル、リロケーションを読み込む。
2. 同名のシンボルや未定義シンボルを検査し、各シンボルの最終アドレスを計算する。
3. セクションのサイズとアラインメントを使って配置先を決める。`.bss`はファイル上のサイズを増やさない。
4. 各リロケーションの種類に従って値を書き込む。未対応の種類は明示的なエラーにする。
5. ELFヘッダと`PT_LOAD`を作り、入口アドレスを設定する。
6. リンク後の未解決参照や不正なセグメント配置を検査する。

現行のRust実装は`R_X86_64_64`、`R_X86_64_PC32`、`R_X86_64_PLT32`、`R_X86_64_32`、`R_X86_64_32S`を扱います。その他はエラーにします。

## セグメント配置

LiseOSの現行`linker.ld`は`.text`に読み取り・実行、`.rodata`に読み取り、`.data`に読み取り・書き込みの権限を指定しています。`.limine_requests`もデータ側に配置します。

アクセス権限の異なる`PT_LOAD`が同じ4 KiBページを共有しないよう、セグメント開始位置をページ単位に揃えます。ELFの`p_offset`と`p_vaddr`は`p_align`に関する整合条件を満たす必要があります。

## Limine用データ

LiseOSでは現状、`linker.ld`の`QUAD`でLimineリクエスト開始・終了マーカーとbase revision 3の値を書いています。Symnexaでは同じ値を生成できるようにするか、Cerune側から入力する方式を用意する必要があります。

リンカ固有の値を無条件で全ELFに追加せず、LiseOS用の指定に限定します。

## 実装時の確認

- 入力のELF形式や未対応リロケーションを正しく拒否する。
- 生成したシンボルアドレスと各セグメントを検査する。
- `ld.lld`の生成物と入口、セグメント権限、Limineマーカーを比較する。
- LiseOSのQEMU/GDBテストでCerune製`main`への到達を確認する。

## Ceruneへの移植

RustのCLIはホスト上で動く初期実装です。Ceruneでバイナリファイル読込・書込とバイト列操作が可能になったら、ELF解析とリロケーション計算をCeruneに移します。既存のRust版と同じオブジェクトを入力し、シンボルアドレスと生成ELF、QEMUの起動結果を比較します。
